## ⚠️ Ограничения MVP

### Функциональные
1. **Лист ожидания** — базовая версия
   - Уведомление отправляется только первому подходящему клиенту
   - Нет автоматического переноса на следующего при отказе
   - Нет очереди с приоритизацией

2. **Telegram Mini App** — минимальная версия
   - Нет валидации `initData` подписи Telegram (нужно для production)
   - Нет встроенного календаря — используется стандартный `<input type="date">`
   - Нет WebApp API интеграции (сворачивания, отправки данных в Telegram)
   - Fallback на localStorage для Telegram ID в dev режиме

3. **Уведомления** — не полностью реализованы
   - Нет асинхронной очереди для отправки
   - Нет механизма повторных попыток при ошибке
   - Нет шаблонизации сообщений
   - Нет отправки напоминаний перед посещением

4. **Мастера**
   - Панель управления только в Telegram (ограниченная функциональность)
   - Нет веб-панели для просмотра записей в календаре
   - Нет автоматических напоминаний клиентам

5. **Клиенты**
   - Минимальная валидация данных контакта
   - Нет системы отзывов и рейтинга
   - Нет сохранения истории клиента в профиле

### Архитектурные
1. **Часовые пояса** — хранятся в UTC, но не всегда корректно обрабатываются
2. **Конкурентность** — защита от race condition только на уровне БД
3. **Масштабируемость** — нет кэширования (Redis)
4. **Аутентификация** — только Telegram ID без дополнительной безопасности
5. **Rate limiting** — не реализован
6. **Сессии** — нет управления сессиями между запросами

### Операционные
1. **Мониторинг** — нет логирования в файл
2. **Аналитика** — нет сбора метрик
3. **Резервные копии** — не настроены
4. **Health checks** — только простой /health endpoint
